# 품질 기준과 실패 대응

## 합격 판정

디자인은 아티스트가 승인한다. 기술 항목은 직접 실행 증거에 따라 PASS/FAIL/NOT_RUN/NOT_REQUIRED. 미정 규격, 필요한 검사 미실행, BLOCKER/MAJOR 미해결은 최종 납품 차단. MINOR는 담당자가 명시적으로 수용할 수 있다. 정적 관찰과 실제 테스트를 구분한다. 이 버전은 자동 검사기가 없으므로 실제 UI/Blender 도구/수작업 검사 결과만 기록한다.

| 검사 | 기준 및 근거 | 실패 대응 |
|---|---|---|
| 디자인 | 승인 원본과 얼굴·헤어·체형·의상 비교, 누락 방향 명시 | 원본/해당 파트 수정 |
| 메시 | 요구 예산, 정상 면·노멀·연결부, 의도치 않은 구멍·관통 | 국소 보정, 의도적 열린 경계는 예외 기록 |
| UV·텍스처 | 요구 UV 세트와 텍스처·재질 누락 확인, 시각적 이음새 확인 | 필요한 UV/재질만 수정 |
| 리그 | 대상 스켈레톤·웨이트·메시 변형, 지정 테스트 포즈 | 해당 관절 및 웨이트 수정 |
| 표정 | 요구 Shape Key/본과 실제 표정, 중간 강도/눈꺼풀/입 검사 | 얼굴 컨트롤 보완 |
| 립싱크 | 필요 시 런타임 viseme/입모양 계약과 실제 연동 | 별도 구현 및 테스트 |
| 모션 | 지정 동작·프레임 구간에서 관통·찢어짐·발 이동 검사 | 리그/모션 보완 |
| 파일 | 대상 포맷·경로·재가져오기 및 런타임 요구사항 | export/호환 보완 |

고정 렌더는 동일 카메라·스케일·조명·포즈·프레임 조건으로 비교한다. 아름다운 한 장의 렌더로 모든 방향과 동작을 통과 처리하지 않는다. 정적 모델에서 리그가 필요 없다면 제작 카드에서 NOT_REQUIRED 승인한다.

## 결함 심각도

- BLOCKER: 사용 불가, 원본 훼손/권한 위반, 핵심 디자인 불일치, 필수 파일/검사 누락.
- MAJOR: 제품 요구에 위배되는 외형/변형/표정/재질 문제.
- MINOR: 실사용을 막지 않는 국소 결함. 담당자 수용 여부 기록.

동일 원인 2회 연속 복구 실패 시 중단한다. 다른 승인 파트를 변경하거나 유료 생성량을 늘리기 전 재승인한다. 원본 정보 부족 / Tripo 생성 편차 / 조립·메시 / UV·재질 / 리깅·표정 / 런타임 호환으로 분류한다. 개선 요청은 관찰 근거에 근거한다.

## P3 자동 QA와 Hook 계획 (미구현)

1. 실제 대상 포맷/규격을 고정하고 메시·텍스처·리그 검사기와 다각도 렌더 검사기를 작성한다. 수치 임계값은 제품 담당자가 확정한다.
2. 정상·고의 결함·의도적 예외 샘플로 검사기 정확도를 확인한다. 정상과 오류를 구분하지 못하는 검사기를 강제 적용하지 않는다.
3. 검사 결과에 파일 버전/해시, 검사기 버전, 검사 범위, 상태와 근거를 남긴다. 변경 후 이전 증거는 영향 범위에 대해 무효화한다.
4. 먼저 명시적으로 검사를 실행하고 최종 출력 게이트를 테스트한다. 이후 실제 지원되는 프로젝트 로컬 Hook 이벤트·스키마·신뢰 설정을 확인한다. PostToolUse는 이미 발생한 효과를 취소하지 않는다. Tripo 비동기 생성 완료나 임의 GUI 저장을 모두 포착한다고 가정하지 않는다.
5. 실제 출력/납품 경로에서 실패·미실행을 차단하는지, 수동 우회 경로가 있는지 검사한다. AI의 Stop 이벤트만으로 보안/납품 강제가 완성된다고 보지 않는다.

[Hook 공식 문서](https://learn.chatgpt.com/docs/hooks). 이 버전에는 활성 Hook 설정이 없다.

## 검수 결과의 유효성

검수 시 작업본/출력 파일의 버전, 검사 시점, 검사 도구, 결과 근거를 기록한다. 수정 이후에는 영향받은 검사를 다시 실행하고 이전 디자인 승인이 여전히 유효한지 담당자가 확인한다. Blender 재가져오기와 실제 제품 런타임 로딩은 별도 항목이다. 해당 런타임에서 시험하지 않았다면 제품 적용 PASS는 금지한다.

## v0.2 검사 및 납품 Gate

위 P3 계획은 v0.1 역사 기록이다. v0.2에는 scripts/blender/qa.py 및 scripts/harness.py gate/deliver가 존재한다. 구조 검사와 Workbench 프리뷰는 실제 Blender 미실행. 메시 연결/UV/재질/본/웨이트/Shape Key 이름 및 보호 시그니처는 일부 자동 검사 범위이며 미적·물리·제품 품질 전체를 보장하지 않는다. 필요한 수동 승인과 최신 파일에 묶인 QA 증거가 없으면 deliver를 거부한다. [HARNESS](HARNESS.md) 참조.
