# 처음 시작하기 — 디자이너용

## 1. 무엇을 준비하면 되나요?

기술 담당자가 Codex, 사용할 모델, Blender 연결을 준비합니다. Tripo 계정과 사용 승인도 확인해야 합니다. 설치를 직접 하거나 코드를 작성할 필요는 없습니다. [설정 가이드](SETUP.md)를 전달하세요.

- 사용할 권리가 있는 원본 이미지(가능하면 정면·측면·후면·얼굴 확대)
- 만들고 싶은 캐릭터 또는 이미 만들어진 3D 파일
- 유지할 특징 3~7개, 변경해도 되는 부분, 최종 사용처
- 담당자가 알려 준 작업 폴더와 사용 가능한 생성 예산

## 2. Codex에서 프로젝트 열기

저장소를 받을 권한이 확보되면 GitHub `Code → Download ZIP`으로 받아 압축을 풉니다. 파일럿 ZIP을 받은 경우에는 받은 ZIP을 풀면 됩니다. 파일 목록에 README.md가 있는 폴더를 열고, 프로그램을 새로 설치하라는 메시지가 나오면 담당자에게 확인합니다. Codex 데스크톱에서 압축을 푼 프로젝트 폴더를 엽니다. 모델 메뉴에 Astra가 있고 사용할 수 있는지 확인합니다. 없으면 기술 담당자와 대체 모델을 정합니다. 일반 웹 채팅은 로컬 Blender에 바로 연결되지 않을 수 있습니다.

## 3. AI에게 첫 요청하기

원본을 AI에 첨부하기 전 외부 제공 허용 여부를 확인하세요. 아래 요청을 복사하면 됩니다. 필요하면 `character-production` Skill을 선택합니다.

```text
이 프로젝트의 AGENTS.md와 character-production Skill을 읽어 주세요.
실제 로드된 Skill, 모델, Computer Use, Blender MCP, Tripo 사용 경로를 확인해 주세요.
새 캐릭터를 만들고 싶습니다. 첨부 원본의 얼굴과 헤어, 의상 디자인을 유지하고 싶습니다.
원본과 제가 유지해야 한다고 말한 특징을 기준으로 제작 카드를 작성해 주세요.
아직 유료 생성, 외부 업로드, 파일 수정, 프로그램 설치는 하지 말고, 가능한 작업과 필요한 승인만 먼저 알려 주세요.
도구가 연결되어 있지 않으면 제가 직접 해야 하는 일을 하나씩 설명해 주세요.
```

이미 모델이 있다면 “새 캐릭터” 대신 “기존 모델의 [부위]만 수정” 또는 “이 모델 검수”라고 요청합니다. 제작 카드 초안은 [양식](../templates/character-spec.md)에 있습니다. 모르는 납품 규격은 미정이라고 말하면 됩니다.

## 4. 첫 생성부터 마무리까지

| 단계 | 내가 할 일 | AI가 보여 줄 것 |
|---|---|---|
| 계획 | 원본 특징·예산 확인 | 생성 방법, 필요 승인, 실제 도구 |
| 생성 | Tripo 후보 1개 승인 또는 직접 생성 | 후보 파일, 사용 크레딧 또는 미확인 |
| 디자인 확인 | 얼굴·헤어·의상·체형 비교 | 정면·측면·후면, 불일치 목록 |
| Blender 수정 | 문제 부위 지목 | 수정 전후 동일 각도 이미지와 새 작업본 |
| 동작 확인 | 필요한 표정·포즈 선택 | 실제 리그·표정·모션 검사 근거 |
| 납품 | 최종 결과 승인 | 최종 파일, 재가져오기 결과, 미검증 항목 |

첫 캐릭터는 모든 자동화를 쓰지 않아도 됩니다. 웹사이트에서 수동 생성한 GLB를 Blender로 불러와 AI에게 수정시키는 경로도 정상입니다.

## 5. 결과가 이상하면

“얼굴은 그대로 두고, 왼쪽 앞머리만 원본처럼 수정해 주세요. 다른 부위는 바꾸지 말고 수정 전후를 같은 각도로 보여 주세요.”처럼 범위를 지정하세요. 같은 오류가 반복되면 AI의 원인 보고를 확인하고 수작업 또는 다른 생성 방법을 선택합니다.

[상세 제작·수정 지시문](PRODUCTION-GUIDE.md) · [검수표](QUALITY-GUIDE.md)

## 6. 작업을 마치거나 다음에 이어서 할 때

AI에게 “오늘 작업한 파일, 수정한 부분, 실제 검사 결과, 남은 문제를 작업 폴더에 정리해 주세요. 원본은 덮어쓰지 마세요.”라고 요청합니다. 다음에 같은 작업을 열 때는 작업 상태부터 확인합니다. 사용하지 않은 기능은 사용했다고 기록하지 않습니다. 제출할 후보의 디자인은 직접 확인하고 승인하세요. 실제 제품에서 테스트하지 않았다면 제품 적용 완료로 표시하지 않습니다.

연결 오류가 나거나 작업 폴더 접근이 안 되면 기술 담당자에게 [연결 검사표](../templates/runtime-check.md)를 전달하세요. 계정 비밀번호나 API 키를 채팅에 붙여 넣지 마세요.

## v0.2 실행 기능

첫 실습은 [HARNESS](HARNESS.md)에서 시작하세요. 기술 담당자가 준비한 승인된 프로젝트 경로를 알려 주면 AI가 상태 확인, 원본 및 GLB 등록, 비교·검사 결과 저장을 진행합니다. 실제 Blender 검사가 불가능하면 결과는 미검증입니다. AI에게 “현재 후보를 검사하고 문제만 수정한 뒤 다시 확인해 주세요. 제가 승인하기 전 납품하지 마세요.”라고 요청하세요.
