# 설계 및 안전 경계

## 목표

3D 생성 엔진을 새로 만들지 않는다. 기존 도구를 이용해 원하는 디자인에 가까운 에셋을 만들고, 수정·검수 시간을 줄일 수 있는지 검증하는 로컬 제작 Harness다. 3D 디자이너가 요청·디자인 판단을 담당하고 기술 담당자는 설치·검사 도구를 담당한다.

## 구성

```text
디자이너 → Codex/Astra(사용 가능 시)
             ↓ AGENTS.md + character-production Skill
             ├─ Tripo Studio / Plugin (한 경로 선택)
             ├─ Computer Use (화면 기반, 지원 시)
             └─ Blender MCP/Python (구조 조작, 승인 시)
             ↓ 실제 렌더/검사 근거 → 디자이너 승인
```

기본: Studio 수동 생성 + Blender + 실제 가능한 AI 제어. 선택: Plugin 직접 생성, Computer Use. 둘 다 제어 불가 시 사람의 수작업으로 대체하고 자동화 실험을 차단으로 표기. P4에서 ComfyUI를 추가하고 Charakuru는 라이선스와 VRM 중심 적합성을 별도 확인한다.

## 데이터·권한

Git에는 도구 지침·스크립트·빈 양식만. 회사 원본·모델·렌더·작업 이력·고객/계정 정보는 승인된 로컬 작업 위치에 보관. `.gitignore`와 실제 Git staged diff 검토를 함께 적용하며 강제 추가 금지. 승인된 샘플도 이용권과 배포 범위를 확인한다. Tripo, 이미지 모델, AI 채팅은 외부 전송 가능성이 있어 계약/보안 검토가 먼저다.

작업 폴더 구조: `references/`, `source/`, `blender/`, `renders/`, `reports/`, `delivery/`. 원본과 승인본은 읽기 전용으로 취급, 수정은 새 버전. Writer 하나만 동일 작업본을 수정. 승인된 샘플에서 검사한 후 생산에 적용한다.

## 상태와 검증

지침은 강제 보안 장치가 아니다. Skill은 절차, MCP는 실행 도구, Hook은 런타임 이벤트 연결, QA는 실제 검사기다. v0.1은 Skill 초안과 수동/AI 보조 검수에 한정. 검사기와 Hook은 P3에서 실제 제품 요구와 샘플 검증 후 구축. 디자인 승인자는 사람. 모델/도구/Skill 로드/기술 검사 PASS는 각각 별도.

P0~P2 키트의 구현 범위는 문서, 지침, 읽기 전용 환경 조회 및 테스트로 한정한다. 제품 고유 리깅·표정·품질 계약과 핵심 자동 수정 로직은 담당자 정의 및 명시적 구현 위임이 필요하다. 별도 검토자는 작성자와 구분한다.
