# 제작·수정 실전 가이드

작업은 [제작 카드](../templates/character-spec.md)와 [품질 기준](QUALITY-GUIDE.md)을 따른다. 각 단계에서 필요한 경우 아래 문구를 복사한다. 새 모델 없이 수정·검수만 수행할 수 있다.

## A. 원본 분석 및 레퍼런스

```text
원본에서 꼭 유지할 얼굴·눈·헤어·체형·의상·색상·장식 특징을 추출해 주세요.
정면 외에 없는 정보는 추정으로 구분하고, 모순되는 다각도 이미지가 있으면 생성 전에 알려 주세요.
동일 캐릭터의 정면·측면·후면과 얼굴 확대를 준비할 방법을 추천해 주세요.
새 디자인 생성은 원하지 않습니다. 승인된 범위 밖으로 바꾸지 말아 주세요.
```

Tripo 공식 튜토리얼은 단색 배경·고른 조명·T/A 포즈와 멀티뷰를 권장한다. LoRA는 스타일 유지에 활용할 수 있지만 다각도 형상 일치를 보장하지 않는다. 생성된 레퍼런스도 디자이너 승인 필요.

## B. Tripo 생성

[Studio](https://studio.tripo3d.ai/)에서 이미지 업로드 → Generate 3D → Smart Topology Mesh/Smart Mesh 계열 선택 → 필요 시 멀티뷰 및 Topology 설정. 화면 명칭은 변동 가능하며 공식 튜토리얼과 실제 화면을 확인한다. 전신 한 개를 기준선으로 생성한다. 얼굴 디테일·헤어가 반복해서 무너지면 머리/몸/헤어 분리 후보를 검토한다. 분리 생성에는 조립·UV·리깅 비용이 추가된다.

```text
승인된 원본과 제작 카드 기준으로 Tripo 후보 1개 생성 계획을 보여 주세요.
현재 화면 또는 실제 플러그인에서 모델, 입력 이미지, 옵션, 예상 크레딧을 확인해 주세요.
비용이 미확인이면 생성하지 마세요. 승인 후 한 번만 생성하고 작업 ID와 결과 파일을 저장해 주세요.
시간 초과/연결 끊김이면 기존 작업 상태를 먼저 확인하고 중복 제출하지 마세요.
Computer Use 또는 Plugin이 없으면 제가 눌러야 할 메뉴를 안내해 주세요.
```

원본 GLB 및 관련 텍스처를 `source/`에 별도 보관한다. 결과가 잘못되면 Tripo Edit Mesh 등 국소 기능의 실제 지원 여부를 확인한다. 전체 재생성은 승인 후.

## C. 디자인 검수

```text
원본과 후보의 정면/측면/후면/얼굴 확대를 동일한 기준으로 비교해 주세요.
얼굴·헤어·체형·의상·실루엣별 차이, 관찰 근거, 심각도, 권장 수정 범위를 보고해 주세요.
원본에 없는 방향은 추정, 관찰하지 못한 항목은 NOT_RUN입니다. 아직 편집하지 마세요.
```

디자이너가 디자인을 승인한 뒤 다음 작업을 진행한다. 피부·헤어가 뚫리거나 형태가 어긋난 경우 렌더 연출로 숨기지 않는다.

## D. Blender 조립 및 국소 수정

Blender `File → Import → glTF 2.0` 등으로 파일을 가져온 후 새 `.blend` 사본을 만든다. 원본 보호. 실제 MCP 연결 또는 UI 제어를 확인한다.

```text
현재 모델의 [수정 대상]만 [원하는 결과]로 수정해 주세요.
먼저 실제 Object·Mesh·Armature 및 수정 전 렌더를 확인해 주세요.
정상 부위와 기존 UV/머티리얼/리그/Shape Key를 보존해 주세요.
Body/Head/Hair 조립이 필요한 경우 실제 크기·축·목 연결·헤어 관통부터 검사해 주세요.
승인된 작업본의 새 버전에서 수정하고 같은 카메라·조명·포즈로 전후 비교해 주세요.
다른 부위가 손상되면 변경을 납품 후보로 사용하지 말고 이전 승인본으로 돌아가 주세요.
```

Computer Use는 시각적 조작에, MCP/Python은 수치·구조 변경 및 반복 검사에 활용. 둘 중 하나만 지원해도 가능한 경로를 선택하되, 직접 실행 불가 시 수동 안내로 바꾼다.

## E. UV·재질·리깅

```text
현재 UV, 텍스처 연결, 머티리얼, Armature, 본, 웨이트 및 메시 연결을 실제 확인해 주세요.
기존 유효 리그를 우선 사용하고 리그 초기화는 하지 마세요.
제작 카드의 대상 엔진/리그 규격에 맞춰 검사해 주세요. 규격이 미정이면 최종 적합성을 단정하지 마세요.
고개 회전·팔 들기·팔꿈치·무릎 굽힘을 작업 사본에서 테스트하고 관통/찢어짐을 기록해 주세요.
문제가 확인되면 해당 관절 웨이트만 수정할 계획을 제안하고 승인 범위 내에서 실행한 뒤 동일 포즈로 비교해 주세요.
```

Tripo Auto Rig는 시작점이다. 실제 요구 리그가 있는지 먼저 확인하고, 본이 존재한다는 이유만으로 통과 처리하지 않는다.

## F. 표정 및 모션

```text
얼굴 Shape Key 또는 얼굴 본이 실제 존재하는지 확인해 주세요.
neutral/blink/smile/mouth-open 중 제작 카드에 필요한 항목을 테스트하고 같은 카메라로 렌더링해 주세요.
립싱크는 별도 요구사항입니다. viseme 또는 대상 런타임의 컨트롤 규격과 연동 증거를 확인해 주세요.
짧은 인사 등 승인된 테스트 동작으로 관절 변형·관통·발 미끄러짐을 확인해 주세요.
구현되지 않은 기능은 추가 제작 필요, 시험하지 않은 기능은 NOT_RUN으로 보고해 주세요.
```

## G. 최종 검수·출력

```text
승인된 제작 카드와 QUALITY-GUIDE.md에 따라 최종 후보를 검수해 주세요.
각 항목의 상태와 근거 파일, 미해결 결함을 기록하고 새 경로에 출력해 주세요.
출력 파일을 새 Blender 장면 또는 대상 런타임에서 재가져와 확인해 주세요.
대상 런타임 검증이 없으면 제품 적용 완료라고 하지 마세요. 디자인과 납품 최종 승인은 디자이너가 합니다.
```

작업 중단 시 `templates/run-state.md`에 현재 파일 버전·승인 범위·작업 ID·다음 행동을 남긴다. 재개 시 최신 상태를 확인한다. 이전 결과를 덮어쓰거나 과금 작업을 중복 실행하지 않는다.
