# 로드맵 및 완료 조건

| 단계 | 현재 상태 | 완료 조건 |
|---|---|---|
| P0 Foundation | 로컬 초안 작성 | 문서·목차·정책 검토 및 Owner 승인, 공개 범위 결정, 원격 반영 |
| P1 실행 환경 | 가이드 및 읽기 전용 doctor 초안 | 대표 디자이너 PC에서 실제 모델, Blender, Tripo, AI 제어 및 대체 경로 확인 |
| P2 제작 Workflow | AGENTS.md·Skill·템플릿 초안 | 실제 로드 확인 및 신규/수정/검수 샘플 완주, 중단·재개 검증 |
| P3 자동 품질 검증 | 계획 | 대상 규격 확정, 검사기 정상/실패/예외 검증, 실제 납품 게이트와 Hook 검증 |
| P4 제작 자동화 | 계획 | 필요성 확인 후 ComfyUI 연동, 라이선스 적격 후보 비교, 반복 복구/비용 제한 검증 |
| P5 실무 도입 | 계획 | 실제 사용자 테스트, 기존 공정 비교, 런타임 검증, 배포·유지보수 및 협력 개선안 |

v0.1의 목표는 제작 지원 키트 초안이다. 제품 적용 가능 상태, 실측 품질 개선, 자동화 완료를 주장하지 않는다. 우선순위: P0 초기 게시 및 검토 → P1 연결과 P2 대표 샘플 → P3 실측 결함 기반. P5의 AS-IS 조사와 P1/P2 파일럿 설계는 병렬 진행 가능. P4는 P3·실험 결과에 따라 선택.

## 원격 반영 전 Owner Gate

- 공개 범위 확인과 최초 Push 승인. 공개 저장소에는 일반 공개 자료만 게시하며 회사 소유/사용 정책은 실제 운영 전 별도 확인한다.
- 회사 자료 포함 여부 검토, Git staged diff와 민감정보 점검. 공개 허용된 일반 자료만 게시.
- 회사 PC 환경 변경 및 유료 생성은 별도 승인.
- 초기 검토본 게시 후 독립 Reviewer가 고정 커밋과 검증 결과를 검토한다. 팀 운영 적용은 독립 검토 및 실제 PC 파일럿 후 판단한다. 작성자의 자기 점검은 독립 Review가 아니다.

## v0.2 업데이트

P0 기존 main 반영 완료. P1/P2: 로컬 관리·도구 사용 절차 구현, 실환경 미검증. P3: 구조 검사 및 프리뷰/게이트 구현, Blender 실통합 NOT_RUN. P4: 스키마 기반 ComfyUI 초안 및 Hook 선택 어댑터 작성, 실제 실행 NOT_RUN. P5: 디자이너 및 제품 파일럿 대기. v0.2는 독립 검토할 부분 구현본이지 생산 환경 READY가 아니다.
